# Project decisions
- Derive mobile greetings and profile labels from the current user's saved profile, auth metadata or email username through a user-keyed query and pure helper; never retain a previous account's name.
- Keep the mobile navigation indicator and route slides presentation-only, respecting reduced motion and the Appearance animations toggle.
- Keep mobile template definitions and text-to-block conversion in one typed catalog so previews, paper choices and interactive task blocks stay consistent.
- Present mobile writing and handwriting preview as separate views of the same editor state; persist mobile block edits immediately so an immediate reload cannot restore an earlier template.
- Persist mobile draft notebook identity in the effect body on every identity change, never in cleanup, so reloads cannot target a previously opened note.
- Share one email/password authentication presentation across /login, /signup and /auth so validation, confirmation states and transitions stay consistent.
- Use a route-aware mobile presentation shell backed by existing notebook and editor hooks; keep desktop routes unchanged so the redesign does not fork product data.
- Keep legal information in public React routes linked from the footer so visitors can read it without signing in.
- Route privileged AI requests through authenticated edge functions; browser bundles must never contain provider secrets.
- Treat authentication storage as essential and optional analytics as consent-dependent so declining tracking does not prevent sign-in.
- Activate paid subscriptions only after server-side provider verification and a unique payment claim; client callbacks and retries cannot grant access.- Keep tracker math (streaks, bill split) as pure helpers in src/lib/trackers.ts with bun tests beside them, so rules stay checkable without the UI.
- PDF import runs page-by-page in the browser (src/lib/pdfPipeline.ts): text-layer pages skip AI, only scanned pages hit OCR with bounded parallelism, so one bad page never fails the document.
- Free-form boards (src/pages/Board.tsx, /board) store page JSON in public.boards and media in the private board-media bucket under {userId}/{boardId}/; pure rules live in src/lib/board.ts with bun tests so pagination/eraser/undo stay checkable.
- Gate account creation and paywalls only through src/config/features.ts (SIGNUP_ENABLED, FREE_TRIAL); guests use Supabase anonymous sign-in so owner-scoped RLS keeps their data private.
- Feature motion graphics (loader, water glass, thank-you, feature art) live in src/components/motion and must respect reduced motion; chart/water math stays in src/lib/trackers.ts with bun tests. Why: one place for animations, rules stay testable.
- The Niknote Habit experience (/habit, src/pages/RoutineApp + src/components/habits) is a self-contained mobile app: screen state lives in a shell (splash → bottom-nav tabs → pushed detail screens), data persists per user in localStorage via src/lib/routineStore.ts, and all rules (streaks, week completion, sleep/exercise math, focus durations, achievements) are pure helpers in src/lib/trackers.ts with bun tests. Supabase is an optional one-way mirror (Backup & Sync) to the legacy /routine tables and a one-time restore source; the app must work fully offline, so never make local state depend on a network round-trip. Seed data on first run pre-unlocks the achievements it already satisfies so first open is quiet.
